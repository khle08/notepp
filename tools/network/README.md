# subnet_relay.sh —— 用一台双网卡服务器打通两个网段

不用写代码，全是 Linux 内核自带的转发 + NAT（iptables），一个脚本管理开、关、端口转发、开机自启。

## 什么时候用

办公室这种结构（2026-10 实测）：

```
光猫 192.168.1.1 ─┬─ 交换机 ── 摄像头 192.168.1.168 等        ← 1 网段（IN 侧）
                 └─ Wi-Fi 路由器（NAT） ── Mac / 服务器 110.x   ← 110 网段（OUT 侧）
```

- **110 → 1 天然就通**：路由器把 110 的流量 NAT 出去，跟上网一样。Mac 直接 ping `192.168.1.168` 没问题。
- **1 → 110 不通**，有两道关：光猫的路由表里没有 110 网段；Wi-Fi 路由器也不放从 WAN 侧进来的连接。
  典型的卡点：摄像头的报警回调要推到 110 网段的平台。
- 有一台服务器**两只脚各踩一个网段**（3090：有线 `enp2s0f0` 在 1 网段，USB Wi-Fi `wlxbcec434317f5` 在 110 网段），就能拿它当中继。

## 30 秒上手

```bash
# 拷到服务器的固定位置（开机自启会记住这个路径，别放 /tmp）
sudo install -m 755 subnet_relay.sh /usr/local/bin/subnet_relay.sh

# 1. 打通：--in 是"要被放进来"的那侧网卡，--out 是目标网段那侧网卡（网段从网卡自动识别）
sudo subnet_relay.sh up --in enp2s0f0 --out wlxbcec434317f5

# 2. 摄像头这类没法加路由的设备：用端口转发
#    1 网段访问 192.168.1.5:3546 → 转到 110 网段的 Mac 上的 ridgeos
sudo subnet_relay.sh forward add 3546 192.168.110.204:3546

# 3. 替身地址（光猫加不了路由时，靠它做到"1 网段访问 110 设备的全部端口"）
sudo subnet_relay.sh scan                        # 先看 1 网段哪些地址被占用
sudo subnet_relay.sh map add 192.168.110.229     # 默认末位相同 → 1 网段访问 192.168.1.229 就是访问这台

# 4. 开机自动恢复（systemd 服务，在 docker 之后启动）
sudo subnet_relay.sh enable-boot
```

## 全部命令

| 命令 | 作用 |
|---|---|
| `up --in <网卡> --out <网卡>` | 打通 IN → OUT，并保存到 `/etc/subnet-relay.conf` |
| `forward add <端口> <IP:端口> [tcp\|udp]` | 端口转发：IN 侧访问"本机 IN 侧 IP:端口"时，转到 OUT 侧的目标 |
| `forward del <端口> [tcp\|udp]` / `forward list` | 删除 / 列出端口转发 |
| `map add <OUT侧IP> [IN侧替身IP]` | 替身地址：给 OUT 网段的设备在 IN 网段认领一个地址，所有端口和协议（含 ping）都通。不给替身 IP 时默认末位相同；加之前用 arping 检查冲突，被占用就拒绝 |
| `map del <OUT侧IP>` / `map list` | 删除 / 列出替身地址 |
| `scan` | 扫描 IN 网段已被占用的地址（挡 ping 的设备也会回应 ARP，照样能扫到） |
| `status` | 查看配置、网卡、当前规则、开机自启状态 |
| `down` | 撤销本脚本加的所有规则（按标签精确删除，不动 Docker 等其他规则；配置文件保留） |
| `apply` | 按配置文件重新应用（开机服务调用的就是它；手工改完配置后也执行这个） |
| `enable-boot` / `disable-boot` | 打开 / 关闭开机自动恢复 |

## 为什么要"替身地址"

IN 侧设备访问 `192.168.110.x` 时，因为目标不在本网段，**一定会把包交给默认网关（光猫）**，中继机根本收不到。
所以光猫加不了路由、设备也改不了路由时，**用真实的 110 地址是不可能打通的**，写程序也绕不开，因为包根本到不了中继机。
唯一的旁路是 ARP 欺骗冒充网关：太脆弱，中继机一掉线整个网段都会断网，不采用。

替身地址的做法：中继机在 IN 网卡上加一个 `/32` 辅助 IP（标签 `<网卡>:sr`），认领 IN 网段里的一个空闲地址。
IN 侧设备访问这个地址时，和访问同网段的设备一样直接送达，不经过光猫；中继机再把包 DNAT 到真正的 110 设备，回程照常伪装。
**IN 侧设备什么都不用改**，只要把目标地址换成替身地址。

## IN 侧设备怎么找到中继

`up` 只负责把中继机配好，还要让 1 网段的设备知道"去 110 网段要找中继机"，三选一：

1. **光猫 / 上级路由加静态路由**：目的 `192.168.110.0/24`，下一跳 `192.168.1.5`（中继机的 IN 侧地址）。全网生效，摄像头什么都不用改。前提是能进光猫后台并且它支持静态路由。
2. **单台电脑加路由**：Linux 用 `sudo ip route add 192.168.110.0/24 via 192.168.1.5`，Mac 用 `sudo route -n add -net 192.168.110.0/24 192.168.1.5`。
3. **端口转发**（摄像头首选）：摄像头的目标地址填 `192.168.1.5:<端口>`，用 `forward add` 转到真正的目标。

> ⚠️ 中继机的 IN 侧地址如果是 DHCP 分配的，要在路由器上绑定，或者改成静态地址，否则地址一变，路由和端口转发就全部失效。

## 原理（排错时看）

1. `net.ipv4.ip_forward=1`：允许内核转发，写进 `/etc/sysctl.d/99-subnet-relay.conf`，重启后仍有效。
2. **FORWARD 放行** IN → OUT，以及回程（`RELATED,ESTABLISHED`）。装了 Docker 的机器，FORWARD 默认策略是 **DROP**，而且 Docker 会重排 FORWARD 链，所以规则放进 Docker 预留给用户的 `DOCKER-USER` 链，并插在它的 `RETURN` 之前。
3. **MASQUERADE**：转进 OUT 网段的包，源地址改成中继机自己的 OUT 侧地址。这样 OUT 网段的设备会把回包发回中继机，不会交给它自己的默认网关然后发丢。
   所以目标机器看到的访问者是**中继机的 110 地址**，不是真实的摄像头 IP。
4. **DNAT**（端口转发）：`PREROUTING` 改目标地址，FORWARD 放行这一条，再做一次伪装。

所有规则都带 `-m comment --comment subnet-relay`：`iptables-save | grep subnet-relay` 一眼就能看全，`down` 也靠这个标签精确删除。重复执行 `up` / `forward add` 不会叠加。

## 局限

- **中继机必须开着**，关机或重启的那几十秒不通（开机服务会自动恢复）。
- **带宽取决于中继机的网卡**：3090 用的是 USB 无线网卡，跑 ssh、网页、报警回调没问题，**扛不住多路视频**。要跑视频，就让两个网段真正合并（Wi-Fi 路由器改 AP 模式，或者把交换机上联改接到 Wi-Fi 路由器的 LAN 口）。

## 实测记录（2026-10-03，3090）

- `up` 之后 6 条规则（放行 2 + 伪装 1 + 端口转发 3），重复执行仍是 6 条。
- 端到端：Mac（110）访问 `192.168.1.5:13546` → 经 Wi-Fi 路由器进入 3090 的有线口（等同于 1 网段的设备访问）→ 转到 Mac 上的 ridgeos `:3546`，返回 HTTP 200；ridgeos 日志里看到的访问者是 `192.168.110.25`（伪装生效）。
- `down` 之后的 iptables 规则集与测试前**逐条一致**，端口转发随之失效。
- 替身地址：Mac `110.204 → 1.204`、Sophon `110.229 → 1.229`。经 1 网段一侧访问：ping 通（5~7ms）；`1.204:3546` 返回 HTTP 200；ssh `1.229` 能登上 Sophon，来访者显示为 `192.168.110.25`。
  映射到已被摄像头占用的 `.168` 时被 arping 拦下。重启服务后替身地址和规则（5 条）都自动恢复。
- 踩过的坑（两次）：`set -o pipefail` 下，`grep` 无匹配时返回 1，脚本会**静默退出、什么都没做**。一次是 `purge_table` 第一次运行时没有旧规则，一次是 `purge_aliases` 没有旧替身。**脚本里凡是 grep 进管道的，都要带 `|| true`。**
